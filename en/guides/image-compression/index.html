How to compress an iPhone photo to 200 KB or another target size

Written and maintained by HugeHard Studio · Updated 29 October 2026

In Workbench (“工作台”), import a photo, open Adjust (“调整”) → File Size (“文件大小”), select KB as the unit and enter 200, then choose JPEG under Format (“格式”). Generate and check the actual file size and pixel dimensions. Processing runs on device and leaves the original unchanged. The app interface is Simplified Chinese; labels below include their on-screen wording.

Set a 200 KB or other target

  1. In Workbench (“工作台”), choose a photo and import it. At the bottom of the image editor, choose Adjust (“调整”), then File Size (“文件大小”).
  2. Turn on Limit File Size (“限制文件大小”), then tap the target value to open the input panel. Choose KB, enter 200, and tap Confirm (“确认”). You can also drag the ruler to set another target. It must be within the range shown for the current source, from the minimum to the source file’s size.
  3. Choose JPEG under Format (“格式”), then return to Adjust (“调整”) to read the file-size note. JPEG and HEIC search encoding quality to try to stay within the target while retaining more quality; whether it succeeds depends on the source. Transparent areas are filled with white when converted to JPEG.
  4. Tap Generate (“生成”), then check the preview, actual file size, output format, and pixel dimensions. The result screen reports the size and whether the target was met; then save or share.
  5. If you need another format, use the same steps with that output selected. JPEG, HEIC, PNG, and GIF use different encoding methods, so the same target may not be achievable in every format.

Target bytes, pixel dimensions, and crop area are different: cropping changes which part of the image remains, pixel dimensions change output width and height, and file size is measured in bytes. See the iPhone photo cropping, rotation, and ratio guide.

When the input is an animated GIF and GIF remains the output format, all frames, frame delays, and the loop count are preserved. Frame count and image complexity affect the size, so meeting a target is not guaranteed.

Limits to keep in mind

Lossless PNG output, keeping original dimensions, and the number and complexity of GIF frames affect file size. Image processing accepts source images up to 80 megapixels, with an output long-edge limit of 8,192 pixels; the app reports files outside its supported range. Do not infer the output size from the target field alone.

Common issue: pixel dimensions pass but the file is still too large

Pixel dimensions and file size are separate checks. A photo can meet a required width and height while its encoded bytes still exceed a limit. If the output is over target, consider changing the format. If smaller pixels are allowed, adjust the maximum edge under Adjust (“调整”) → Pixel Size (“像素尺寸”); the app does not enlarge the source. Generate again and inspect the actual file.

Why can a PNG stay above 200 KB?

PNG uses lossless encoding and does not make a file smaller by lowering image quality, so it may not reach 200 KB or another target. If the material and use allow, choose JPEG instead. JPEG does not preserve transparency; transparent areas are filled with white. If you must keep PNG, check the actual output size.

“At most 200 KB” versus “strictly under 200 KB”

In This Pic Can Change, 1 KB is 1,000 bytes, so 200 KB is 200,000 bytes. The app counts a target as met when actual bytes are less than or equal to the target: exactly 200,000 bytes meets “at most 200 KB” but not “strictly under 200 KB.” For a strict limit, set a target below 200 KB to leave room, then check the exported file’s exact bytes. Do not rely on a rounded KB display.

Check the file before sharing

Confirm the required format, pixel dimensions, and actual file size. If the target is missed, use the generated file and result message as your reference. Compression writes a new file and leaves the source unchanged.
